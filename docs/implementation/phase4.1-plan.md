## Three deliverables

1. Large, traceable starter corpus: aim 500+ useful source/concept records, ideally1000 if genuinely justified. Multiple catalog/collection sources, Egyptian/Arab/Middle Eastern and African representation plus global material. Store short original summaries and useful extracted structures, NOT large full texts. Keep distinct counts for externally grounded records, authored synthetic Hekayti blocks/families, catalog-only leads, and disposable 5000-record performance fixtures. Never pad the real count with the latter, guessed plots, duplicate editions or cosmetic renamings. Report actual count and any shortfall rather than invent provenance.
2. Compatible provenance/cultural extensions and reusable validated JSON/JSONL batch ingestion. Default profile EGYPTIAN_ARAB_MUSLIM_FAMILY is a selectable editorial preference, not a claim all Arabs are Muslim or all stories religious. READY/NEEDS_ADAPTATION/SENSITIVE_REVIEW/NOT_DEFAULT with explicit factor findings, multidimensional adaptation suggestions and separate RELIGIOUS_ACCURACY_REVIEW_REQUIRED. No invented religious claims; origin descriptive, never quality score. Unreviewed rights metadata never blocks initial collection. Sensitive/not-default material not silently selected in ordinary generation; explicit review/selection policy documented. Cultural/rights statuses remain separate from story approval.
3. Dedicated versioned portable creative-library ZIP export/restore, separate from source recovery and future private operational data. Do NOT zip the mixed app SQLite database, project/workflow/customer/photo tables or generation packages containing requests. Explicit allowlisted creative projection preserves families/seeds/concepts/blocks/source+cultural+editorial metadata and useful usage summaries, with provenance/reference remapping policy. Operational approval references must not become forged current workflow approvals on import; preserve them as historical attribution or report deferred references. Never silently drop data. Exclusion report and explicit synthetic/public-creative declaration; human review remains necessary for free-text privacy. Private canary tests must prove excluded table/field boundaries. Independent empty restore and merge need full schema/hash/count/ref validation, deterministic preview, conflict choices, exact-id replay/idempotency, no overwrite by default and atomic rollback. Same-name similar families may coexist; exact identities/conflicting revisions must be handled explicitly.
