## Decisions and boundaries

Story Source Strategy = HYBRID BY DEFAULT. CURATED and AI-led remain explicit alternatives. No API dependency in current production prototype: no API keys, network generation, consumer-site login/automation/scraping, real personal data, illustration/video/website/photo work. Consumer target labels are user-selected routing notes, never proof of a model or superior quality.

1. Portable strict versioned library records: idea seed, existing StoryConcept payload, structural story family, existing component/building block, approved story reference. Explicit lifecycle generated/saved/reviewed/approved/promoted/archived; inbox distinct from curated library. Human actions control promotion. Family/variant references valid and variant numbers unique; similarity intent is not duplicate rejection. Editorial scores are optional internal human opinion, not validated science.
2. Additive transactional SQLite migration from v2, preserving all old projects/workflows/approvals. Repository abstraction, validation on read/write, CAS and atomic lifecycle/usage updates. No silently repairing corruption or double-counting retries. Small explicit synthetic starter seed is idempotent, not commercially approved content.
3. Pure hybrid preparation: request + current Age/Language guidance + selected versioned library context + four variation intents. Explicit FIXED BY HEKAYTI versus OPEN FOR AI CREATIVITY. Immutable generation-package identity/request revision/context snapshot and versioned output schema, normally 3–5 candidates. Same schema for ChatGPT/Gemini/generic; no unjustified model-specific rules. Clear JSON instructions/example, local validation and copy-ready repair instructions; no guarantee a consumer model obeys schema.
4. Import is untrusted data, never instructions, trusted facts, provider identity proof or approval authority. Bound size/count, reject invalid versions/types/enums/ownership/relations and malformed JSON without partial writes. Source/provider/model notes authored by operator, preserved separately from transport/manual-import provenance. AI output enters inbox; no automatic promotion.
5. Reuse canonical StoryConcept/Blueprint/QA/approval pipeline. Explicit local import/selection boundary, additive provenance-aware workflow version if needed; legacy workflow/1.0 rules and hashes remain readable. Do not loosen old mock provenance globally. Never replace creative imported semantics with stock mock content. Unsupported deterministic drafting must fail readably; a minimal structured manual draft handoff/import through existing edition contracts is allowed if needed to carry general imported concepts through existing QA/approval. No second story engine or fake successful arbitrary prose generation.
6. Minimal UI: library filters/family variants, inbox lifecycle/actions, manual package copy/paste/repair, source/provider notes, quality feedback and explicit use-now into current workflow. Keep renderer isolated and IPC strict. User must manually review synthetic-only package before copying externally.
