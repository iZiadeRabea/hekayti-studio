## Changes and contracts

Desktop explicitly selects `planner-quality/1.1`, producing strict `story-plan/1.2` with `quality.categoryIntent`, and `plan-qa/1.2` with advisory `CategoryPresence: REVIEW`. Original default legacy service, explicit quality1.0, strict StoryPlan1.0/1.1 and their validation/hash paths remain unchanged. Category intent includes category/signature/storyNeeds and participates in the new plan hash. Persistence recomputes its category and objective intent from the retained request through the existing source-validation seam; no SQL migration or new DB authority.

New prepared packages are `plan-package/1.1`, frozen with the same internal acceptance/hash/request/blueprint/concept ownership. External AI receives human-readable Arabic package sections and a small strict response schema instead of a serialized internal package. Per-page active participants are distinct from the canonical allowed dialogue actors. ChatGPT/Gemini/Generic differ only by formatting label; plan, schema and logic are identical.

```json
{"schemaVersion":"writer-response/1.0","editions":[{"mode":"ar-EG","pages":[{"pageNumber":1,"narration":"نص الصفحة","dialogue":[{"speaker":"c1","text":"حوار قصير"}],"altText":"وصف الصفحة"}]}]}
```

Exactly one edition per requested mode and pages1–N exactly once are required. Array order is normalized to request modes and canonical page order. Dialogue speaker must resolve to exactly one cast entry by exact displayName or short key c1/c2, then pass the unchanged canonical beat-actor permission. Unknown/ambiguous/disallowed speakers fail; no name guessing. Strict schemas reject all supplied counts/technical ownership fields, including UUIDs, page/beat IDs, source revisions, concept/package IDs, languageVersionId and provenance. App creates fresh draft/edition IDs, page IDs from the current Blueprint, current source/concept ownership, manual-paste provenance and draft statuses; `countWords` measures narration plus dialogue, excluding alt text.

`plannerCommand PREVIEW` takes the same projectId/packageId/json/expectedPlanner/expectedWorkflow fields as IMPORT. It returns `{planner,preview:{status,diagnostics,editions}}`; diagnostics are `{code,message,mode?,pageNumber?,speaker?}`, summary editions are `{mode,pageCount,totalWords}`. Preview allocates temporary in-memory IDs only and performs canonical language/age/Blueprint safety checks; it does not retain drafts, mutate planner/workflow/Library or use provider/clipboard. REVIEW remains conservative because human native/literary/continuity judgment is always needed. IMPORT reruns source/package/hash/current acceptance/Blueprint/CAS and canonical validation, then uses the existing workflow import transaction. Preview is not an import token or authority. Legacy packages retain `plan-response/1.0` parser, envelope and import path; legacy preview is explicitly labeled for human review.
