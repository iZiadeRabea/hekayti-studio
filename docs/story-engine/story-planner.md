## Retained Phase4.2 architecture

Planning runs before external prose. `PlanningRequest/1.0` wraps the existing StoryRequest and adds cultural profile, one of four variation modes, exact optional family reference, optional fictional character/setting, creator constraints and separate inspiration/adaptation/sensitive/religious controls. No request, Age Engine or Language Engine is duplicated.

Deterministic retrieval ranks latest eligible families, complete DNA/pattern vectors and building blocks by structure, age/type/objective/profile, actual operational use/approval/rejection and actual ratings. Themes alone never establish family identity. Unknown DNA stays null; sparse idea seeds are available as Library research but cannot silently become executable patterns. Known family/DNA fields yield versioned derived editorial blocks with source field/revision, never new claimed source facts.

The starter remains 791 GENERATED records and zero READY rows. No promotion rule is bypassed. Creator-reviewed provisional inspiration is a separate mode, requiring explicit adaptation acknowledgment where needed. Sensitive/not-default and religious-review material require separate deliberate opt-ins; changing profiles never clears flags. Default is EGYPTIAN_ARAB_MUSLIM_FAMILY, with no unsolicited religious instruction.

Structural vector mechanism/attempt/turn categories alter actual action sequences. The age adapter changes recognition/routine/plot forms, cast, beat count and actions. Infants receive four sensory/repeated units without a conventional problem/stakes/climax; toddlers three supported routine units; two-year-olds four linked units; preschool five; older provisional band seven. The numbers are editorial starting choices. Supported strategies and closure are composed around the requested objective and success scenario; delivery of arbitrary objectives still needs human judgment.

SimilarVersion strongly retains the selected family and structural actions. NewVariant retains family while changing a major attempted strategy. FreshConcept prefers another family/structural vector. CompletelyNew also prefers unused structure. No unused alternative is disclosed and changes VariationCompliance to REVIEW. Regeneration cycles eligible ranked candidates; no fine-tuning, vector database or hidden chain-of-thought exists.

Selecting an IDEA_SEED with known exact family membership retains both the member and that family as contributing source revisions, with the member first. Family eligibility and cultural consent also apply; obsolete member-to-family revisions are not silently rebound. Same-family or same-pattern reuse through a different member is still disclosed, not labelled structurally new. Acceptance creates a GENERATED variant in the actual family and actual feedback updates both member and family once.

StoryPlan records goal/problem/setup/state/location/cast, ordered actions, causes, turns/resolution/ending and qualitative QA. Plan acceptance binds SHA256 and exact request/source revisions. Changing the current plan invalidates current canonical derivatives while retaining history; source revisions block package use/import and downstream QA/approval. Ratings conservatively create a source revision, so another plan is needed before further generation. Historical text approvals remain historical evidence.

Historical approvals cannot authorize fresh Library extraction after planner/source drift, including the direct persistence path for a new approved reference. Previously stored approved references and frozen plans remain unchanged.

Accepted plans use additive workflow/1.2 single-plan concept sets, select/build the existing Blueprint, then manual prose import, existing QA and explicit text approval. Legacy workflow/1.0 and /1.1 payloads/hashes remain unchanged. Planner-bound approvals additionally hash the frozen planner source; there is no fabricated multi-candidate import. Accepted-plan concepts enter GENERATED Library variants with `planner-derived` origin; acceptance is not text approval or promotion. Actual variant counts derive from those records; real feedback creates idempotent usage outcomes and source score revisions.

SQLite retains append-only plans/acceptances/packages/feedback with CAS and a sealed payload, exact canonical relationships and a permanent initialization marker. This is an additive v3 extension; legacy operational data is not rewritten. A checksum detects accidental corruption, not an adversary able to rewrite the complete database. Planner histories are operational state and are excluded from the portable creative projection; the separate public/synthetic Library variants retain declared creative lineage.

Minimal UI lives within Story Creator: create/reopen request → planning choices → Plan Story → plan/logic QA → change family/regenerate → accept/build → prepare/copy manual package → paste planned prose → existing QA/approval → real review feedback. Optional selected character is available in the strict reusable contract; no full character editor is introduced. Creator free-text constraints are recorded for human/manual review, not certified by a classifier. No renderer Node/network capability, paid API, browser login or consumer automation is added.

Consolidated offline UI verification: `node --import tsx scripts/phase42-ui-smoke.mjs`, or append `--packaged` after `npm run package:win`. Creates isolated ignored userdata, exercises three clipboard formats/live structured import/canonical QA/test approval/feedback/restart, and independently restores a creative ZIP containing the new reusable variant without planner history.
